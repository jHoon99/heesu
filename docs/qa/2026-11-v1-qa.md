# 희수영어 v1 QA 체크리스트 (2026-11)

일요일 시연 뒤 며칠 동안 직접 써 보며 확인하는 목록이에요. 개발 지식 없이 따라 할 수 있게 썼어요. 클라우드 설정 명령은 여기에 다시 쓰지 않고 [배포 런북](../deploy/2026-11-cloud-runbook.md)의 절 번호로 안내해요.

## 쓰는 법

- 항목 모양: `- [ ] **확인할 것** — 방법 → 기대: 보여야 하는 결과 (기기)`. 기대와 다르면 체크하지 않고 이슈로 남겨요.
- 이슈에는 **날짜 · 기기 · 주소(URL) · 화면 캡처 · 내가 한 일** 다섯 가지를 적어요. 주소에 `#t=…`(학부모 링크 토큰)가 있으면 지우고 캡처해요.
- 기기 약어는 항목 끝에 붙어 있어요.

| 약어 | 기기 |
| --- | --- |
| PC | PC Chrome, 창 너비 1280px |
| iOS | 아이폰 Safari |
| iOS앱 | 아이폰 홈 화면에 추가한 앱 |
| AND | 안드로이드 Chrome |
| 카톡 | 카카오톡 안에서 여는 인앱 브라우저 |

- 시험 주소는 배포 미리보기 `https://dev.heesu.pages.dev`예요(운영은 `https://heesu.pages.dev`). 커밋별 주소(`<hash>.heesu.pages.dev`)에서는 로그인하지 않아요.
- 계정 준비(비밀번호는 비밀번호 관리자에서 꺼내 쓰고 여기나 채팅에 적지 않아요).
  - 원장: 런북 §6에서 만든 원장 계정(비밀번호 12자 이상 + 인증 앱 TOTP).
  - 학생: `demo_haneul`(김하늘 (예시), 중2, 중등 기초반), `demo_minjun`(이민준 (예시), 고1, 고등 독해반). 시드가 만든 `demo_seoyeon`·`demo_jiwoo`·`demo_siwoo`(중등), `demo_doyun`·`demo_yuna`·`demo_harin`(고등)은 화면 목록용이라 로그인 계정이 없어요.
  - 다른 학생의 데이터가 안 보이는지 보려면 학생 계정이 둘 필요해요(`demo_haneul`, `demo_minjun`).
- 시연 데이터의 사람 이름은 모두 `(예시)`가 붙은 가짜예요. 전화는 `010-0000-00xx`예요.

## 상태를 쓰는 항목 (시연 전에 다시 채워야 해요)

아래 표시 **[소모]**가 붙은 항목은 한 번 하면 시연 데이터 상태가 바뀌어요. QA가 끝나면 시연 전날 밤에 런북 §6 "시연 전날 밤 (1)"대로 `supabase/seed-demo-clear.sql` → `supabase/seed-demo.sql`을 SQL Editor에서 차례로 실행해 되돌려요(학생 계정은 남고 학부모 링크는 지워져서 다시 만들어요).

- **[소모] 포인트 +3 축하**: `demo_haneul` 27점에서 +3을 주면 학생 화면에 축하가 한 번만 떠요. 다시 보려면 리셋하거나 랜딩 관리에서 목표를 바꿔요.
- **[소모] 수업 시작**: 오늘 수업이 만들어져요. 리셋하면 사라져요.
- **[소모] 첫 로그인 비밀번호 변경**: 계정마다 **딱 한 번**만 볼 수 있어요. 시연에서 보여 주려면 QA에서는 `demo_minjun`으로만 하고 `demo_haneul`은 아껴 둬요. 이미 썼다면 원장 화면에서 "비밀번호 초기화"로 임시 비밀번호 상태로 되돌려요.
- **[소모] 숙제 "제출했어요"**, **질문 보내기·답변**: 리셋하면 시드 상태로 돌아가요.

## 1. 방문자 (`/`, `/privacy`)

- [ ] **섹션 순서와 모션** — 로그아웃 상태로 `/`를 위에서 아래로 스크롤해요 → 기대: 소개 → 수업 방식 → 반과 시간표 → 원장 소개 → 수강료 → 오시는 길 → 상담 신청 순서이고 글이 부드럽게 올라옴. 모션 줄이기를 켜면 움직임이 없음 (PC, iOS)
- [ ] **히어로 문구** — 맨 위를 봐요 → 기대: "한 문장씩, 깊이 있게." 와 "2027년 1월 개원 · 전주 중·고등 영어" (PC, iOS)
- [ ] **공지 띠** — 랜딩 관리에서 공지를 켠 상태로 봐요 → 기대: 맨 위에 공지 띠가 보이고, 시드 상태에서는 `(예시)`로 시작함 (PC, iOS)
- [ ] **반과 시간표가 DB 값** — 랜딩 관리에서 반 이름을 바꿔 저장해요 → 기대: 새로고침 후 랜딩 "반과 시간표"에 바뀐 이름이 보임 (PC)
- [ ] **수강료가 DB 값** — "수강료 (월)"과 "교재비" 줄을 봐요 → 기대: 랜딩 관리에 넣은 금액과 같음. 값이 없으면 빈칸 자리표시가 보임 (PC, iOS)

- [ ] **전화 `tel:`** — "전화로 문의하기"를 눌러요 → 기대: 전화 앱이 해당 번호로 열림. PC에서는 주소가 `tel:`로 시작함 (iOS, AND)
- [ ] **지도 앱 링크** — "지도 앱에서 보기"를 눌러요 → 기대: 지도 앱이나 지도 페이지로 이동 (iOS, AND)
- [ ] **주소 복사** — "주소 복사"를 눌러요 → 기대: "주소를 복사했어요." 안내. 복사가 막히면 "복사하지 못했어요. 주소를 길게 눌러 복사해 주세요." (iOS, AND)
- [ ] **상담 폼 연락처 숫자만** — 연락처 칸에 `01012345678`만 입력해요 → 기대: `010-1234-5678` 모양으로 자동 정리됨 (iOS, AND)
- [ ] **상담 폼 형식 문구** — 연락처를 `0101`처럼 짧게 두고 보내요 → 기대: "010-0000-0000 형식으로 입력해 주세요." (PC)
- [ ] **확인란 둘 다 필수** — "보호자가 작성합니다 (필수)"와 "개인정보 수집·이용 동의 (필수)"를 하나씩만 체크하고 보내요 → 기대: 안 한 쪽에 "보호자만 신청할 수 있어요. 확인란을 체크해 주세요." 또는 "개인정보 수집·이용에 동의해 주세요." (PC, iOS)

- [ ] **390px에서 가로 스크롤 없음** — 창 너비 390px(또는 아이폰)에서 `/`와 `/privacy`를 훑어요 → 기대: 옆으로 밀리지 않음. 랜딩 관리에 긴 공지(500자)를 넣어도 그대로 (PC, iOS)
- [ ] **`/privacy` 검색 제외** — 주소창에 `/privacy`를 열고 개발자 도구 없이 런북 §8의 `curl -s $H/privacy | grep -i noindex` 결과를 옮겨 적어요 → 기대: `noindex`가 나옴(공개 전 관문에서만 사라져야 함) (PC)

## 2. 원장 (`/admin/*`)

사이드바 메뉴는 오늘 · 출결·숙제 · 수업일지 · 학생 · 반 · 영상 · 질문 · 상담 · 포인트 · 결제 · 랜딩 관리 · 설정이에요.

### 로그인·TOTP

- [ ] **잘못된 비밀번호** — 틀린 비밀번호로 로그인해요 → 기대: "아이디 또는 비밀번호가 맞지 않아요. 다시 입력해 주세요." (PC)
- [ ] **TOTP 필수** — 비밀번호만 맞히고 인증 코드 단계에서 주소창에 `/admin`을 직접 입력해요 → 기대: 열리지 않고 인증 코드 화면으로 돌아감 (PC)
- [ ] **TOTP 등록 QR** — 처음 로그인하는 원장 계정(런북 §6 끝에서 준비용 TOTP를 지운 상태)으로 로그인해요 → 기대: "인증 앱 등록용 QR 코드"가 깨지지 않고 보임 (PC, iOS)
- [ ] **로그인 시도 제한** — 틀린 코드를 여러 번 넣어요 → 기대: 어느 순간 "로그인 시도가 너무 많아요. 5분 뒤 다시 시도해 주세요." (PC)

### 오늘

- [ ] **오늘 카드** — `오늘`을 열어요 → 기대: 월·일·요일 날짜, "오늘 수업", "미답변 질문", "새 상담" 숫자가 보임 (PC)
- [ ] **수업 시작 [소모]** — 오늘 시간표가 있는 반의 "수업 시작"을 눌러요 → 기대: 출결·숙제 화면으로 이어지고 그 반 학생 칸이 보임. 이미 수업이 있으면 같은 수업이 열림(중복 안 생김) (PC)
- [ ] **알려진 동작: 자정 넘긴 탭** — 밤새 켜 둔 탭을 새로고침 전에 봐요 → 기대: 어제 날짜로 남아 있고, 새로고침하면 오늘로 바뀜(시연 뒤 고칠 목록) (PC)

### 출결·숙제

- [ ] **출결 칸 저장과 되돌리기** — 칸을 누른 뒤 안내의 "되돌리기"를 눌러요 → 기대: 이전 값으로 돌아감 (PC)
- [ ] **숙제 칸** — 숙제 완료 칸을 눌러요 → 기대: 학생이 제출한 항목은 "제출 …"로 보이고, 완료·미완료는 원장이 정함 (PC)
- [ ] **오늘 수업 추가** — "오늘 수업 추가"를 눌러요 → 기대: "오늘 수업을 추가했어요." 아직 수업이 없으면 "아직 수업이 없어요. 오늘 수업 추가를 눌러 시작해 주세요." (PC)
- [ ] **알려진 동작: 최근 8회에 미래 수업** — 미래 날짜 수업을 하나 만들어 표를 봐요 → 기대: "최근 8회"에 미래 날짜 수업이 섞여 보일 수 있음(시연 뒤 고칠 목록) (PC)
- [ ] **알려진 동작: 퇴원생 지난 칸** — 퇴원 처리한 학생의 지난 칸을 고치려 해 봐요 → 기대: 표에는 보이지 않고 원장도 그 칸을 고칠 수 없음 (PC)

### 수업일지

- [ ] **일지 저장** — 반을 고르고 날짜·수업 내용·숙제를 적어 저장해요 → 기대: "수업일지를 저장했어요." (PC)
- [ ] **마감일 검증** — 숙제 마감일을 수업 날짜보다 앞으로 골라요 → 기대: "숙제 마감일은 수업 날짜와 같거나 그 뒤로 골라 주세요." (PC)
- [ ] **같은 날 중복** — 같은 반·같은 날짜로 또 저장해요 → 기대: "이 반은 그 날짜에 이미 수업이 있어요. 목록에서 그 날짜를 열어 고쳐 주세요." (PC)

### 학생

- [ ] **목록 검색** — 검색칸에 이름이나 아이디 일부를 넣어요 → 기대: 일치하는 학생만 남음("이름이나 아이디로 찾기") (PC)
- [ ] **학생 추가** — 아이디 `qa_test1`, 학년, 이름, 8자 이상 임시 비밀번호로 추가해요 → 기대: "학생을 추가했어요. 아이디와 초기 비밀번호를 학생에게 알려 주세요." 목록에 보임 (PC)
- [ ] **아이디 형식** — 아이디에 `AB`처럼 대문자·2자를 넣어요 → 기대: "아이디는 영문 소문자·숫자·밑줄(_)로 3~20자로 입력해 주세요." (PC)
- [ ] **학교·보호자 두 번 연속 저장** — 학생 상세 "학교·보호자"에서 학교를 적고 저장, 이어서 보호자 이름을 바꿔 다시 저장해요 → 기대: 두 번 다 "보호자 정보를 저장했어요."이고 새로고침해도 두 값이 모두 남음 (PC)
- [ ] **보호자 연락처 형식** — 보호자 연락처에 `1234`를 넣어 저장해요 → 기대: "010-0000-0000 형식으로 입력해 주세요." (PC)
- [ ] **반 배정** — 반 배정을 바꿔 저장해요 → 기대: "반 배정을 저장했어요." 반 목록 인원이 바뀜 (PC)
- [ ] **동의 기록** — 동의 일시와 동의서 버전(예: 2026-11)을 적어 추가해요 → 기대: "동의 기록을 추가했어요." 미래 일시는 "동의 일시는 지금보다 앞이어야 해요." (PC)
- [ ] **학부모 링크 만들기** — 링크를 처음 만들어요 → 기대: 링크가 한 번 보이고, 만들기 전에는 "아직 만든 링크가 없어요. 링크를 만들어 학부모님께 카톡으로 보내 주세요." (PC)
- [ ] **학부모 링크 재발급** — "새 링크 만들기" → "새 링크를 만들까요?"에서 확인해요 → 기대: 새 링크가 나오고 옛 링크는 못 씀 (PC)
- [ ] **학부모 링크 복사** — 복사 버튼을 눌러요 → 기대: "링크를 복사했어요. 카톡으로 보내 주세요." 안 되면 "복사하지 못했어요. 링크 칸을 눌러 직접 복사해 주세요." (iOS, PC)
- [ ] **결제 기록 카드** — 학생 상세 "결제 기록"을 봐요 → 기대: 월·금액·납부일·메모 표. 기록이 없으면 "아직 결제 기록이 없어요." (PC)
- [ ] **비밀번호 초기화** — "비밀번호 초기화" → 새 초기 비밀번호 입력 → 확인해요 → 기대: "비밀번호를 초기화했어요. 새 비밀번호를 학생에게 알려 주세요." 그 학생이 다음 로그인에서 새 비밀번호를 정해야 함 (PC)
- [ ] **퇴원 처리** — QA용 학생에게 "퇴원 처리할까요?"를 확인해요 → 기대: 목록 기본 보기에서 사라지고, 반·출결 표에서도 빠짐 (PC)

### 반

- [ ] **반 추가와 시간표** — 반 이름, 구분, 시간표(`17:00`처럼), 정원으로 저장해요 → 기대: "반을 저장했어요." 목록에 시간표와 인원이 보임 (PC)
- [ ] **시간표 검증** — 끝나는 시각을 시작보다 빠르게, 또는 같은 요일에 겹치게 입력해요 → 기대: "끝나는 시각을 시작보다 늦게 적어 주세요." / "같은 요일에 겹치는 시간이 있어요. 시간을 고쳐 주세요." (PC)
- [ ] **같은 이름 반** — 이미 있는 반 이름으로 저장해요 → 기대: "이미 같은 이름의 반이 있어요. 다른 이름을 입력해 주세요." (PC)
- [ ] **일요일 칸 유지 여부** — 고등 독해반의 일요일 칸을 봐요 → 기대: 시연용 일요일 14:00–16:00이 있음. 누나가 필요 없다 하면 지움(§8 질문) (PC)

### 영상

- [ ] **업로드 진행률** — 짧은 mp4(50MB 미만)를 올려요 → 기대: 진행률(%)과 MB가 올라가고, 끝나면 "저장했어요." 목록에 보임 (PC)
- [ ] **50MB 넘는 파일 거절** — 50MB가 넘는 mp4를 올려요(Free 한도) → 기대: "파일이 너무 커요. 영상을 나누거나 화질을 낮춰 다시 올려 주세요." (PC)
- [ ] **mp4가 아닌 파일** — `.mov`나 사진을 골라요 → 기대: "mp4 파일만 올릴 수 있어요." (PC)
- [ ] **제목 필수** — 제목을 비우고 올려요 → 기대: "제목을 입력해 주세요." (PC)
- [ ] **끊긴 업로드 이어 올리기** — 업로드 중 인터넷을 끊었다 켜요 → 기대: 끊기면 안내가 뜨고 연결되면 이어서 올릴 수 있음 (PC)
- [ ] **시청 현황** — 학생이 본 뒤 원장 영상 목록을 봐요 → 기대: 학생별 "본 구간"과 "다 본 학생" 수가 보임(학생 기기가 알려 준 값이라 증빙은 아님) (PC)
- [ ] **영상 삭제** — "이 영상을 지울까요?"를 확인해요 → 기대: "영상을 지웠어요." 학생 목록에서도 사라짐 (PC)

### 질문

- [ ] **미답변 배지** — 학생이 질문을 보낸 뒤 사이드바 "질문"을 봐요 → 기대: 미답변 숫자가 보이고, 목록 위 탭에도 "미답변" 숫자가 있음 (PC)
- [ ] **실시간 도착** — 원장 `질문` 화면을 열어 둔 채 학생이 질문해요 → 기대: 새로고침 없이 목록에 뜸. 없으면 "새 질문이 없어요. 학생이 질문하면 여기에 바로 떠요." (PC, iOS)
- [ ] **답변 보내기** — 답변을 적어 보내요 → 기대: "답변을 보냈어요." 미답변에서 빠지고 학생 화면에 "원장님 답변"이 보임 (PC)

### 상담

- [ ] **새 신청이 먼저** — `상담` 목록을 봐요 → 기대: "새 신청" 상태가 맨 위, 이어서 신청일 순 (PC)
- [ ] **상태 바꾸기와 메모** — 한 건을 열어 상태를 "연락함"·"보류"로 바꾸고 메모를 적어 저장해요 → 기대: "상담 기록을 저장했어요." 목록에 바뀐 상태가 보임 (PC)
- [ ] **메모 길이** — 메모에 2001자를 넣어요 → 기대: "메모는 2000자까지 쓸 수 있어요." (PC)

### 포인트

- [ ] **순위표** — `포인트`를 열어요 → 기대: 순위·이름·학년·포인트 표이고 재원 학생만 보임("순위는 재원 학생만 세요."). 동점은 같은 순위 (PC)
- [ ] **수동 가감 사유 필수** — 학생을 골라 포인트 `3`, 사유를 비우고 저장해요 → 기대: "사유를 1~100자로 입력해 주세요." (PC)
- [ ] **포인트 범위** — `0` 또는 `150`을 넣어요 → 기대: "포인트는 -100부터 100 사이의 0이 아닌 정수로 입력해 주세요." (PC)
- [ ] **음수 표시** — `-2`에 사유를 적어 저장해요 → 기대: 내역에 음수로 보이고 누적 포인트가 줄어듦 (PC)
- [ ] **사유가 학생에게 보임** — 사유 칸의 안내를 봐요 → 기대: "학생 화면에도 보여요. 학생이 봐도 괜찮은 말로 적어 주세요." (PC)
- [ ] **내역 50건** — 내역이 50건을 넘는 학생을 봐요 → 기대: "최근 50건만 보여요" 안내 (PC)

### 결제

- [ ] **월 이동** — 월 이동 버튼으로 지난달·이번 달을 오가요 → 기대: 지난달은 8명 모두 납부일(그달 5일), 이번 달은 `한하린 (예시)`만 미납 (PC)
- [ ] **칸 입력** — 빈 칸(예: `정도윤 (예시)` 이번 달)을 눌러 금액·납부일·메모를 넣어 저장해요 → 기대: "결제 기록을 저장했어요." 칸에 "n월 n일 납부" (PC)
- [ ] **납부일 비우기** — 납부일을 비워 저장해요 → 기대: 미납으로 보임("비워 두면 미납으로 보여요.") (PC)
- [ ] **기록 지우기** — "기록 지우기"를 누르고 "한 번 더 누르면 지워져요"에서 한 번 더 눌러요 → 기대: "결제 기록을 지웠어요." (PC)
- [ ] **금액 범위** — 금액에 `99999999`를 넣어요 → 기대: "금액은 0~10,000,000원 사이 숫자로 입력해 주세요." (PC)
- [ ] **안내 문구** — 화면 아래 안내를 읽어요 → 기대: "금액과 납부일을 직접 적는 기록이에요. 실제 결제와 연결되지 않아요." (PC)

### 랜딩 관리

- [ ] **공지 저장 즉시 반영** — 공지 제목·본문을 적고 "랜딩에 공지 띠 보이기"를 켜 저장해요 → 기대: "랜딩에 반영했어요." 랜딩을 새로고침하면 띠가 보임 (PC)
- [ ] **공지 제목 필수** — 띠를 켠 채 제목을 비워요 → 기대: "공지를 보이려면 제목을 입력해 주세요." (PC)
- [ ] **연락처 저장** — 전화·주소를 바꿔 저장해요 → 기대: 랜딩 푸터 연락처와 `tel:` 링크가 바뀜 (PC, iOS)
- [ ] **잘못된 전화 거절** — 전화에 `1588-1234`나 `abc`를 넣어요 → 기대: "전화번호는 063-000-0000처럼 숫자와 -로 입력해 주세요." (`0XX-XXX(X)-XXXX` 형식만 받음. 1588·070은 아직 받지 않음) (PC)
- [ ] **반·시간표 편집** — 반을 추가하고 "아래로 옮기기"로 순서를 바꾼 뒤 저장해요 → 기대: 랜딩 순서가 바뀜. 11번째 반은 "반은 10개까지 넣을 수 있어요." (PC)
- [ ] **수강료·교재비 편집** — 금액을 바꿔 저장해요 → 기대: 랜딩 "수강료"에 바로 반영 (PC)
- [ ] **법정 표시 저장** — 학원 명칭·등록번호·교습과목·교습비 게시 문구를 넣어 "법정 표시 저장"을 눌러요 → 기대: 랜딩 푸터에 반영 (PC)
- [ ] **목표 바꾸면 다시 축하** — 보상 목표를 30에서 35로 바꾸고 `demo_haneul`이 35에 닿을 때 학생 화면을 봐요 → 기대: "학생 홈 포인트 카드의 목표예요. 바꾸면 학생이 새 목표에 닿을 때 한 번 더 축하해요." 대로 새 목표에서 축하가 한 번 더 뜸 (PC, iOS)
- [ ] **목표 범위** — 목표에 `0`이나 `20000`을 넣어요 → 기대: "목표는 1~10000 사이 숫자로 입력해 주세요." (PC)

### 설정

- [ ] **원장 비밀번호 변경** — 설정 "비밀번호 변경"에서 새 비밀번호(12자 이상 권장)를 두 번 넣어요 → 기대: "비밀번호를 바꿨어요." 두 칸이 다르면 "두 비밀번호가 달라요. 같은 비밀번호를 한 번 더 입력해 주세요." (PC)
- [ ] **짧은 비밀번호** — 7자를 넣어요 → 기대: "8자 이상으로 입력해 주세요." (PC)
- [ ] **같은 비밀번호** — 지금과 같은 비밀번호를 넣어요 → 기대: "지금 비밀번호와 다른 비밀번호를 입력해 주세요." (PC)

### 화면 너비

- [ ] **1024px 미만 사이드바 접힘** — 창을 1000px로 줄여요 → 기대: 사이드바가 접히고 메뉴 버튼으로 열림. 1280px에서는 항상 보임 (PC)

## 3. 학생 (`/s/*`)

학생 탭은 홈 · 숙제 · 영상 · 질문 · 내 정보예요.

- [ ] **첫 로그인 강제 변경 [소모]** — 처음 로그인하는 학생으로 로그인해요 → 기대: 학생 홈 대신 "새 비밀번호를 정해 주세요"가 뜸. 바꾸기 전에는 다른 화면으로 못 감 (iOS, AND)
- [ ] **강제 변경 검증** — 새 비밀번호를 임시 비밀번호와 같게 넣어요 → 기대: "지금 비밀번호와 다른 비밀번호를 입력해 주세요." (iOS)
- [ ] **약한 비밀번호** — `12345678`을 넣어요 → 기대: "너무 쉬운 비밀번호예요. 숫자와 영문을 섞어 8자 이상으로 바꿔 주세요." (iOS)
- [ ] **홈 구성** — 비밀번호를 바꾼 뒤 홈을 봐요 → 기대: 인사("오늘도 한 문장씩!"), 오늘 숙제 카드, "내 포인트", 새 영상 카드가 보임 (iOS, AND)
- [ ] **포인트 카드** — 포인트 카드를 봐요 → 기대: 점수, "보상까지 n점 남았어요", 순위는 "전체 n명 중 n등"처럼 숫자만 (iOS)
- [ ] **숙제 제출 [소모]** — `숙제`에서 항목의 "제출했어요"를 눌러요 → 기대: 버튼이 "제출했어요 · 시각"으로 바뀌고 원장 출결·숙제 표에 제출로 보임. 화면 위 안내: "다 했으면 ‘제출했어요’를 눌러 주세요. 완료·미완료는 원장님이…" (iOS, AND)
- [ ] **미완료가 위에 남음** — 숙제 목록을 봐요 → 기대: 제출하지 않은 숙제가 위쪽에 남고 마감 지난 것은 "마감 지남"으로 보임 (iOS)
- [ ] **숙제 없음** — 숙제가 없는 학생으로 봐요 → 기대: "지금은 할 숙제가 없어요." 또는 "아직 숙제가 없어요." (AND)
- [ ] **영상 목록** — `영상`을 열어요 → 기대: 내 반 영상만 보이고 안 본 영상은 "아직 안 봤어요", 없으면 "아직 새 영상이 없어요." (iOS, AND)
- [ ] **영상 재생** — 영상을 눌러요 → 기대: 같은 화면에서 재생되고, 위쪽에 "영상 목록" 돌아가기 링크가 있음 (iOS, AND)
- [ ] **이어 보기** — 영상을 일부 보고 나갔다가 다시 들어와요 → 기대: 본 곳 근처에서 이어짐, 목록에 "이어서 본 것" 표시 (iOS, AND)
- [ ] **영상 못 찾음** — 주소의 `id=`를 지워 열어요 → 기대: "영상을 찾을 수 없어요. 목록에서 다시 골라 주세요." (PC)
- [ ] **질문하기** — 영상 화면이나 숙제 항목의 "질문하기"를 눌러요 → 기대: 질문 화면으로 이동하고 "무엇에 대한 질문인가요?"에 그 영상/숙제가 골라져 있음 (iOS)
- [ ] **질문 보내기** — `질문`에서 내용을 적어 보내요 → 기대: "질문을 보냈어요. 원장님이 답하면 여기에 보여요." 목록에 "아직 답변을 기다리고 있어요." (iOS, AND)
- [ ] **답변 실시간** — 질문 목록을 열어 둔 채 원장이 답해요 → 기대: 새로고침 없이 "원장님 답변"이 나타남 (iOS, AND)
- [ ] **질문 길이** — 2001자를 넣어요 → 기대: "2000자까지 쓸 수 있어요." (PC)
- [ ] **내 정보** — `내 정보`를 열어요 → 기대: "포인트 내역"(사유 포함), "비밀번호 변경", "홈 화면에 추가하기", "로그아웃"이 보임. 내역이 없으면 "아직 포인트 내역이 없어요." (iOS, AND)
- [ ] **설치 안내 문구** — "홈 화면에 추가하기" 카드를 읽어요 → 기대: 아이폰/안드로이드 방법이 있고 "아이폰은 Safari와 홈 화면 앱의 로그인이 따로예요", "카카오톡에서 열었다면 먼저 Safari나 Chrome으로 열어 주세요." (iOS, AND, 카톡)
- [ ] **비밀번호 변경이 현재 비밀번호를 묻지 않음** — `내 정보` > 비밀번호 변경을 열어요 → 기대: 현재 비밀번호 칸 없이 새 비밀번호와 확인만 있고 "비밀번호를 바꿨어요."로 끝남. 이게 괜찮은지는 §8에서 누나에게 물어봐요 (iOS)
- [ ] **로그아웃** — "로그아웃"을 눌러요 → 기대: `/login`으로 가고, 뒤로 가기를 눌러도 학생 화면이 보이지 않음 (iOS, AND)
- [ ] **없는 아이디** — 로그인 화면에 없는 아이디를 넣어요 → 기대: "아이디 또는 비밀번호가 맞지 않아요. 다시 입력해 주세요." (PC)

## 4. 학부모 (`/g#t=…`)

- [ ] **기록 화면** — 학부모 링크를 열어요 → 기대: "학습 기록" 제목, 학생 이름, "최근 4주 출결·숙제", "이번 주 수업", 숙제(마감 표시), "누적 포인트", 아래에 "궁금한 점은 학원에 문의해 주세요." (iOS, AND)
- [ ] **영상 기록 없음** — 화면에서 영상 시청 기록을 찾아요 → 기대: 없음(학부모에게는 영상 시청을 보여 주지 않음) (iOS)
- [ ] **토큰이 주소창에서 지워짐** — 링크를 열고 주소창을 봐요 → 기대: 주소가 `/g`만 남고 `#t=…`가 없음 (PC, iOS, AND)
- [ ] **새로고침 유지** — 열린 화면에서 새로고침해요 → 기대: 같은 기록이 다시 보임 (PC, iOS)
- [ ] **지워진 주소를 남에게 보내기** — 주소창의 `/g`를 복사해 다른 브라우저(시크릿 창)에 열어요 → 기대: "링크가 만료되었거나 올바르지 않아요. 학원에 새 링크를 요청해 주세요." (PC)
- [ ] **재발급 뒤 옛 링크 실패** — 원장이 "새 링크 만들기"를 한 뒤 옛 링크를 열어요 → 기대: 같은 실패 문구 (PC)
- [ ] **한 글자 바꾼 링크** — `#t=` 값의 마지막 글자를 바꿔 열어요 → 기대: 같은 실패 문구 (PC)
- [ ] **쿼리로 넣은 토큰** — `/g?t=<토큰>`으로 열어요 → 기대: 같은 실패 문구(토큰은 `#`로만 읽음) (PC)
- [ ] **퇴원 처리 뒤** — 학생을 퇴원 처리한 뒤 그 링크를 열어요 → 기대: 같은 실패 문구 (PC)
- [ ] **응답 헤더** — 런북 §5의 `curl -sI $H/g` 결과를 옮겨 적어요 → 기대: `referrer-policy: no-referrer` 한 줄, `x-robots-tag: noindex` (PC)

## 5. 기기별

### 아이폰 홈 화면 앱

- [ ] **홈 화면 추가** — Safari에서 공유 버튼 > "홈 화면에 추가"해요 → 기대: 희수영어 아이콘이 홈 화면에 생김, 이름이 잘리지 않음 (iOS)
- [ ] **standalone** — 홈 화면 아이콘으로 열어요 → 기대: 주소창 없이 앱처럼 열림 (iOS앱)
- [ ] **하단 safe-area** — 학생 하단 탭을 봐요 → 기대: 탭이 홈 표시줄(아래 가로 막대)에 가리지 않고 아래 여백이 있음 (iOS앱)
- [ ] **앱에서 다시 로그인** — Safari에서 로그인한 상태로 홈 화면 앱을 처음 열어요 → 기대: 로그인 화면이 뜨고 다시 로그인하면 됨(Safari와 앱의 로그인은 따로예요) (iOS앱)
- [ ] **영상 playsinline 재생** — 앱에서 영상을 틀어요 → 기대: 전체 화면으로 튀지 않고 화면 안에서 재생 (iOS, iOS앱)
- [ ] **이어 보기** — 앱에서 영상을 보다 나가서 다시 들어와요 → 기대: 보던 곳부터 이어짐 (iOS앱)
- [ ] **축하가 따로 한 번씩** — Safari에서 축하를 본 뒤 앱에서 다시 열어요(저장소가 따로라서 [소모]) → 기대: Safari에서 한 번, 앱에서 한 번 뜨는 것은 정상이고 각각 두 번째부터는 안 뜸 (iOS, iOS앱)

### 안드로이드

- [ ] **앱 설치 메뉴** — Chrome 오른쪽 위 메뉴(⋮)를 열어요 → 기대: "홈 화면에 추가"(또는 앱 설치)가 보이고 추가하면 아이콘이 생김 (AND)
- [ ] **설치 앱 실행** — 아이콘으로 열어요 → 기대: 주소창 없이 열리고 로그인 상태가 유지됨 (AND)

### 카카오톡 인앱

- [ ] **학부모 링크 열기(아이폰)** — 카톡 채팅에서 학부모 링크를 눌러요 → 기대: 인앱 브라우저에서 기록이 보임 (카톡)
- [ ] **학부모 링크 열기(안드로이드)** — 같은 방법 → 기대: 기록이 보임 (카톡)
- [ ] **새로고침** — 인앱에서 새로고침해요 → 기대: 같은 기록이 다시 보이거나, 주소에서 토큰이 지워진 경우 실패 문구가 보임(둘 중 어느 쪽인지 적어 둬요) (카톡)
- [ ] **링크 미리보기에 토큰 없음** — 카톡에 링크를 보낸 뒤 말풍선 미리보기 카드를 봐요 → 기대: 카드에 학생 이름·기록·토큰이 보이지 않고 학원 이름 정도만 보임 (카톡)
- [ ] **학생 로그인 안내** — 카톡 인앱에서 학생으로 로그인한 뒤 `내 정보`의 "홈 화면에 추가하기"를 봐요 → 기대: "카카오톡에서 열었다면 먼저 Safari나 Chrome으로 열어 주세요." 안내가 보임 (로그인 화면 자체에 별도 안내가 없으면 시연 뒤 고칠 목록으로 이슈를 남겨요) (카톡)

### PC

- [ ] **원장 전 화면 1280px** — PC Chrome 1280px에서 사이드바 메뉴 12개를 모두 열어요 → 기대: 가로 스크롤 없이 표가 읽히고 깨진 글자·겹침이 없음 (PC)

## 6. PWA·오프라인 (배포 미리보기, production 빌드)

서비스 워커는 production 빌드에서만 등록돼요. 개발 서버가 아닌 `dev.heesu.pages.dev`에서 확인해요.

- [ ] **서비스 워커 등록** — 개발자 도구 없이, 홈 화면 앱을 두 번째 열어요 → 기대: 두 번째 실행부터는 비행기 모드에서도 `/s` 학생 화면의 틀이 뜸 (iOS앱, AND)
- [ ] **오프라인 문구** — 비행기 모드에서 학생 화면의 데이터 요청을 시도해요 → 기대: "인터넷에 연결되지 않았어요. 연결을 확인하고 다시 시도해 주세요." (iOS앱, AND)
- [ ] **알려진 한계: 첫 방문 직후 오프라인** — 앱을 처음 연 직후 새로고침하기 전에 비행기 모드를 켜고 열어요 → 기대: 학생 화면 틀이 안 뜰 수 있음(서비스 워커가 새로고침 뒤에야 페이지를 맡음) (iOS앱)
- [ ] **알려진 한계: 오프라인 새로고침** — 오프라인 상태로 학생 화면을 새로고침해요 → 기대: 몇 초 빈 화면 뒤 역할 확인 오류 문구가 뜸(시연 뒤 고칠 목록). 연결을 켜고 다시 열면 정상 (iOS앱, AND)
- [ ] **영상 화면 `?id=` 캐시 1개** — 영상 두 개를 차례로 연 뒤 오프라인으로 열어 봐요 → 기대: 영상 화면 틀이 `id`마다 따로 쌓이지 않고 하나만 캐시됨. 영상 자체는 오프라인에서 안 나옴 (AND)
- [ ] **Storage 영상이 SW를 거치지 않음** — 영상을 끝까지 보고 중간을 건너뛰어 봐요 → 기대: 건너뛰기(범위 요청)가 끊김 없이 되고 재생이 정상 (iOS, AND)
- [ ] **서비스 워커 응답** — 런북 §5 "서비스 워커" 결과를 옮겨 적어요 → 기대: `/s`가 `200`, `sw.js`가 `cache-control: no-cache` (PC)

## 7. 보안 (도구 없이)

- [ ] **가입 시도** — 로그인 화면에 회원가입 링크가 있는지 봐요 → 기대: 없음 (PC, iOS)
- [ ] **가입 API 차단** — 런북 §5 "가입 차단" curl 결과를 옮겨 적어요 → 기대: `signup_disabled` (PC)
- [ ] **학생이 `/admin` 주소 입력** — 학생으로 로그인한 채 주소창에 `/admin`을 입력해요 → 기대: 학생 홈으로 돌아옴 (iOS, PC)
- [ ] **원장 TOTP 없이** — 원장 비밀번호만 입력하고 코드를 넣지 않은 채 `/admin`을 열어요 → 기대: 열리지 않음(aal2 없이는 관리 화면이 없음) (PC)
- [ ] **다른 학생 데이터 안 보임** — `demo_haneul`로 로그인해 홈·숙제·영상·질문·내 정보를 모두 봐요 → 기대: `demo_minjun`·반 친구의 이름·포인트·출결이 어디에도 없고 순위는 숫자만 (iOS)
- [ ] **질문에 `<script>`** — 학생 질문에 `<script>alert(1)</script>`를 보내요 → 기대: 글자 그대로 보이고 아무것도 실행되지 않음, 원장 화면에서도 같음 (iOS, PC)
- [ ] **학부모 링크 위조** — 한 글자 바꾼 링크, `?t=`로 넣은 링크, 토큰 없는 `/g`를 열어요 → 기대: 모두 같은 "링크가 만료되었거나 올바르지 않아요…" 문구라서 어떤 경우인지 구별할 수 없음 (PC)
- [ ] **퇴원 처리** — 학생을 퇴원 처리하고 그 학생 계정으로 로그인해요 → 기대: 데이터가 0건이거나 "로그인할 수 없는 계정이에요. 학원에 문의해 주세요."이고 학부모 링크도 실패 (PC, iOS)
- [ ] **원장 비밀번호 변경 뒤 다른 기기** — 기기 A에서 원장으로 로그인한 채 기기 B에서 비밀번호를 바꿔요 → 기대: A는 다음 세션 갱신 때 로그아웃됨. 접속 토큰이 최대 1시간 유효해서 즉시는 아닐 수 있음(알려진 한계) (PC, iOS)
- [ ] **로그아웃 후 뒤로 가기** — 학생·원장 모두 로그아웃하고 뒤로 가기를 눌러요 → 기대: 개인 정보가 화면에 남지 않고 로그인 화면으로 감 (PC, iOS)
- [ ] **Realtime 격리** — 학생 A의 질문 화면을 열어 둔 채 학생 B가 질문해요 → 기대: A 화면에는 B의 질문이 실시간으로도, 새로고침 뒤에도 안 보임 (iOS, PC)
- [ ] **Realtime 공개 끈 상태에서 동작** — 대시보드 Realtime "Allow public access"가 꺼진 상태에서 원장·학생 질문 화면을 열어요 → 기대: 로그인한 사용자의 질문·답변은 실시간으로 도착함 (PC, iOS)
- [ ] **옛 refresh token** — 원장 비밀번호를 재설정한 뒤 이전 기기의 옛 로그인 상태로 새로고침을 오래 반복해요 → 기대: 결국 로그인 화면으로 돌아감(클라우드에서 옛 refresh token이 실패하는지 확인) (PC)
- [ ] **CORS 외부 출처** — 런북 §5 CORS 세 줄 결과를 옮겨 적어요 → 기대: 외부 출처는 `403`, 허용 출처만 2xx (PC)
- [ ] **테스트 계정 없음** — 런북 §5 마지막 SQL 결과를 옮겨 적어요 → 기대: `@example.test` 계정이 `0` (PC)

## 8. 누나에게 받을 정보 · 확인할 것

일요일 시연에서 받아 적어요. 채워지면 사이트 내용은 원장 `랜딩 관리`에서, 코드 문구는 PR로 고쳐요.

### 받을 정보

- [ ] **원장 이력** — 소개 글에 쓸 이력 → 기대: 원장 소개에 들어갈 문장을 받음 (PC)
- [ ] **주소** — 정확한 주소와 주차·대중교통 안내 → 기대: 랜딩 관리 "주소"에 넣고 지도 앱 링크가 맞음 (PC)
- [ ] **전화번호** — `0XX-XXX(X)-XXXX` 형식(예: `063-123-4567`)으로 받아요. 1588·070 번호는 아직 받지 않아요 → 기대: 랜딩 관리 "연락처"에서 저장되고 `tel:`이 맞음 (iOS)
- [ ] **교습비·교재비** — 교육청에 신고한 금액 → 기대: 랜딩 "수강료"에 반영됨 (PC)
- [ ] **반·시간표** — 개원 반 구성과 요일·시간 → 기대: 랜딩 관리 "반·시간표"와 원장 `반` 화면 둘 다 맞춤 (PC)
- [ ] **법정 표시 4개** — 학원 명칭, 학원 등록번호, 교습과목, 교습비 게시 문구 → 기대: 랜딩 관리 "법정 표시"에 넣으면 푸터에 보임 (PC)
- [ ] **개인정보 문의처** — 개인정보 보호책임자와 문의처 → 기대: `/privacy` 8번 항목의 빈칸이 채워짐 (PC)
- [ ] **공지 문구** — 첫 공지(개원 일정 등) → 기대: 랜딩 관리 "공지 저장"으로 반영됨 (PC)
- [ ] **보상 목표** — 지금은 30점 → 기대: 누나가 정한 점수를 랜딩 관리 "보상 목표"에 넣음 (PC)

### 누나에게 물어볼 것

- [ ] **등록 동의서에 수업 녹화·영상 게시 동의** — 실제 등록 서류에 이 항목이 있는지 물어요 → 기대: 있음(없으면 서류에 추가). 영상은 학생에게 최대 3시간 열리는 주소로 보이니 그 점도 알려 줌 (PC)
- [ ] **학생 비밀번호 변경이 현재 비밀번호를 안 물어도 되는지** — §3의 확인 결과를 보여 줘요 → 기대: 괜찮다 / 물어야 한다 중 하나로 답을 받음 (PC)
- [ ] **일요일 수업 칸 유지 여부** — 고등 독해반 일요일 14:00–16:00은 시연용이에요 → 기대: 유지/삭제 결정 (PC)
- [ ] **보상 목표 30점** — 목표가 적당한지 물어요 → 기대: 유지하거나 새 점수를 정함 (PC)
- [ ] **포인트 규칙** — 출석 + 숙제 완료 = 1점이 맞는지 물어요 → 기대: 맞다고 확인하거나 규칙을 새로 받음 (PC)

## 9. 12/1 랜딩 공개 전 관문

[런북 §8](../deploy/2026-11-cloud-runbook.md)을 모두 끝내야 주소를 공개로 나눠요.

- [ ] **`(예시)`가 랜딩에 없음** — 런북 §8 첫 쿼리 `select key from public.site_content where value::text like '%(예시)%';`를 돌리고 랜딩을 눈으로 훑어요 → 기대: 0행이고 랜딩 어디에도 `(예시)`가 없음 (PC, iOS)
- [ ] **실제 전화번호** — 랜딩 연락처를 봐요 → 기대: 가짜 번호 `063-000-0000`이 아닌 실제 번호이고 `tel:`이 맞음 (iOS, AND)
- [ ] **진짜 Turnstile 키** — 런북 §8의 순서(사이트 키 PR → 운영 배포 → 비밀 교체 → 함수 재배포)대로 바꿔요 → 기대: 실제 신청 1건이 성공하고 위젯이 실제로 검증함. 허용 호스트는 `heesu.pages.dev`, `dev.heesu.pages.dev` (PC, iOS)
- [ ] **Turnstile hostname 검사** — 함수가 응답의 hostname을 검사하는 후속 항목을 진짜 키와 같이 처리했는지 봐요 → 기대: 다른 주소에서 받은 토큰은 거절됨 (PC)
- [ ] **시연 데이터 삭제** — 런북 §8 "시연 데이터를 지워요"를 따라 clear SQL, 학생 정리, Auth 사용자·영상 파일 삭제를 해요 → 기대: `demo\_%` 학생이 0명이고 원장 화면에 `(예시)`가 없음 (PC)
- [ ] **`/privacy` 관문** — 빈칸 채움, 없는 기능 문구 제거, 법률 검토, `noindex` 제거, `sitemap.xml`에 추가 → 기대: `curl -s $H/privacy | grep -i noindex`가 비어 있음 (PC)
- [ ] **시연 뒤 고칠 목록 처리** — `docs/superpowers/plans/v1-followups.md`의 "시연 뒤 · 12/1 전" 묶음을 봐요 → 기대: 각 항목이 고쳤거나 미룸 사유와 함께 정리됨 (PC)
- [ ] **운영 주소에서 마무리** — 런북 §7 뒤 `https://heesu.pages.dev`에서 §5를 다시 해요 → 기대: 모든 `확인:`이 맞고 원장 로그인·학생 홈·학부모 링크 3개가 동작 (PC, iOS)

## 11. 알려진 한계 (v1)

- [ ] **영상 주소 3시간** — 학생이 받은 영상 signed URL을 3시간 안에 다른 곳에 붙여 넣어요 → 기대: 최대 3시간 동안 열릴 수 있음(권한 있는 학생 본인에게만 발급됨) (PC)
- [ ] **Realtime 삭제 이벤트** — 질문·답변이 지워지는 순간을 봐요 → 기대: 삭제 알림에는 id만 실려 와서 화면이 목록을 다시 불러옴 (PC)
- [ ] **로그아웃한 원장의 접속 토큰** — 로그아웃한 원장 토큰은 만료(최대 1시간)까지 유효해요 → 기대: 알려진 한계이며 비밀번호 재설정 뒤 갱신에서 끊김 (PC)
- [ ] **고아 영상 파일** — 업로드가 끝난 직후 행 저장 전에 탭을 닫아요 → 기대: 영상 목록에는 없지만 Storage에 파일이 남음. 대시보드 Storage `videos`에서 직접 지움(정리 화면은 v1에 없음) (PC)
