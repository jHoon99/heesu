# 랜딩(Landing) 구현 계획 — v1 계획 1/7

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/`(랜딩 시안 그대로 + `site_content`에서 읽는 섹션 + 상담 신청 폼 → Edge Function `submit-consultation`)과 `/privacy`, SEO 파일을 로컬에서 끝까지 동작하게 만들고, 기반 계획의 랜딩 후속 항목을 모두 닫는다.

**Architecture:** 랜딩은 정적 HTML로 굽고(코드 문구 + DB 섹션의 기본 자리표시), 브라우저가 `site_content`를 anon으로 읽어 덮어쓴다. 상담 신청은 테이블 insert가 아니라 Edge Function(Deno)이 Turnstile 검증 → service_role 전용 RPC `submit_consultation`(전화번호별 24시간 3건 제한, 동의 버전·시각 저장)을 부른다. 기능 폴더는 `features/landing`(화면), `features/site-content`(읽기), `features/consultations`(폼)로 나눈다.

**Tech Stack:** Next.js 16.4.4 (static export) · React 19.3 · Tailwind v4 · TanStack Query 5 · react-hook-form 7 + zod 4 · supabase-js 2.118 · Supabase CLI 2.121 · pgTAP · Deno 2.9 (Edge Functions) · Cloudflare Turnstile · Vitest

**Spec:** `docs/superpowers/specs/2026-11-04-heesu-v1-features-design.md` (§3 랜딩, §10 항목 1, §11 중 랜딩 관련) · 구조·보안은 `docs/superpowers/specs/2026-11-03-heesu-architecture-design.md` (§4, §5, §6, §13 S2·S4·S6·S10·S12·S14) · 후속 항목 `docs/superpowers/plans/foundation-followups.md` "Landing plan must include" · 디자인 원본 `docs/design-system/landing-mock.html`, `README.md`, `motion.md`, `develop.md`

## Review Focus

1. **`site_content` 값이 비었거나 모양이 틀린 경우**(원장이 일부 키만 저장, 숫자 자리에 문자열, 알 수 없는 키) → 그 섹션만 자리표시로 남고 페이지는 멀쩡해야 한다. → Task 5 `parseSiteContent` 테스트(잘못된 값·빈 문자열·알 수 없는 키).
2. **Supabase에 닿지 않는 경우**(오프라인, 프로젝트 일시 정지) → 랜딩은 자리표시로 전부 보이고 오류 토스트가 뜨지 않는다. → Task 5 `useSiteContent` 테스트(data 함수 reject → `EMPTY_SITE_CONTENT`).
3. **연락처를 이상하게 넣는 경우**(`+82 10-1234-5678` 붙여넣기, 공백·하이픈 섞기, 12자리 이상) → 숫자만 남기고 `010-1234-5678`로 맞추거나 고치는 방법을 보여 준다. → Task 6 `formatPhoneInput` 표 테스트.
4. **느린 망에서 "상담 신청하기"를 두 번 누르는 경우** → 요청은 한 번만 간다. → Task 6 ConsultForm 테스트 "pending 중 두 번 클릭 → 1회 호출".
5. **Turnstile이 안 뜨거나 토큰이 없는/만료된 경우**(광고 차단, 위젯 오류, 제출 실패 뒤 일회용 토큰 재사용) → 조용히 무시하지 않고 고치는 방법을 보여 주며, 실패 뒤에는 위젯을 다시 받는다. → Task 6 ConsultForm 테스트 "토큰 없음 → 안내, 요청 없음", "captcha 실패 → 토스트 + 위젯 리셋"; Task 4 handler 테스트 "토큰 검증 실패 → 400 captcha".
